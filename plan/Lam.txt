  6. Với Model Information: version, ngày train, thuật toán và trạng thái.

Sản phẩm bàn giao: Danh sách chức năng, use case/user flow, wireframe 4 trang.
Tiêu chí nghiệm thu: Mỗi trang có mục đích và dữ liệu cần hiển thị; không có màn hình không liên quan đề tài.
Phụ thuộc / phối hợp: Trao đổi HI01 để chốt nội dung form dự báo.

L02 | GĐ2 | Xây dựng Backend API
-----------------------------------------------------------------------------
Mục đích: Tạo FastAPI làm trung gian giữa Frontend và model Machine Learning.
Các bước thực hiện:
  1. Tạo backend/app/main.py, schemas/prediction.py, services/predictor.py, api/routes.py.
  2. Cài fastapi, uvicorn và dependency Python cần thiết.
  3. Khởi tạo FastAPI(title=Retail Demand Forecast API).
  4. Tạo GET /health trả status healthy.
  5. Tạo GET /model-info trả thông tin model khi có (trước đó dùng trạng thái chưa sẵn sàng, không báo metric giả).
  6. Chạy uvicorn và mở /docs kiểm tra Swagger.
Công cụ / file: Python; FastAPI; Uvicorn; backend/app/main.py; http://localhost:8000/docs.
Sản phẩm bàn giao: Backend skeleton; GET /health; GET /model-info; Swagger docs.
Tiêu chí nghiệm thu: Chạy API local được; /health trả 200; Swagger mở được.
Phụ thuộc / phối hợp: Cần HI01 để chốt API contract; L03 sẽ dùng model thật sau khi HI05 xong.
Trạng thái theo bản kế hoạch: Chưa bắt đầu

L03 | GĐ3 | Tạo API dự báo
-----------------------------------------------------------------------------
Mục đích: Xây POST /predict để gọi model thật thay vì dữ liệu mô phỏng.
Các bước thực hiện:
  1. Nhận best_model.joblib, hàm predict và feature order từ Hiếu.
  2. Chốt request store_id, item_id, horizon (ví dụ 7).
  3. Backend kiểm tra input, lấy lịch sử bán từ nguồn dữ liệu thống nhất với Hùng/Hiếu.
  4. Gọi hàm dự báo của Hiếu; với dự báo nhiều ngày phải dùng quy tắc multi-step thống nhất.
  5. Trả JSON model_version và forecast [{date,predicted_sales}].
  6. Test trên Swagger với store/item có lịch sử đủ dài và test khi thiếu input.
Công cụ / file: FastAPI; backend/app/services/predictor.py; POST /predict; Swagger.
Sản phẩm bàn giao: POST /predict chạy bằng model thật; JSON response mẫu; test request thành công/lỗi.
Tiêu chí nghiệm thu: Response đúng số ngày dự báo, không trả dữ liệu giả hoặc NaN; input sai có thông báo rõ.
Phụ thuộc / phối hợp: Phụ thuộc HI05 và dữ liệu lịch sử Hùng; bàn giao endpoint cho L04/L05 và Quân.
Trạng thái theo bản kế hoạch: Chưa bắt đầu
